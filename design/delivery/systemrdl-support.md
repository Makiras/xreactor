# SystemRDL 支持计划

状态：TODO，尚未实现。记录日期为 2026-10-01。

计划为 XReactor 增加可选的 SystemRDL 接入流程，让项目从寄存器规格生成 Python 访问包，再连接已有的总线 Agent。第一阶段推荐复用 PeakRDL-Python，采用构建时生成、运行时绑定的方式。设计理由与替代方案见[寄存器模型设计](../architecture/systemrdl-register-model.md)。

本计划记录后续工作，不表示已新增公共 API、依赖或生成工具。实施优先级由[路线图](roadmap.md)统一管理；具体接口在最小示例验证后确定。

## 第一阶段的目标

完成一个可重复构建、可以通过 XReactor 访问的小型寄存器示例。用户修改 RDL 后，通过项目构建入口更新访问包；测试通过具名寄存器和字段操作访问 DUT，无需在测试中重复维护地址与位移常量。

生成任务作为独立构建目标提供，由项目决定是否与 Picker 导出一起执行。RDL 编译器和生成器作为可选构建依赖，普通 XReactor 测试环境按需加载生成包。

## 生成工作流

- [ ] 选择并固定 SystemRDL Compiler 与 PeakRDL-Python 的兼容版本，确认生成包的部署依赖。
- [ ] 提供明确的生成入口，接收文件列表、include 搜索路径、顶层地址映射、参数和输出目录。
- [ ] 生成异步 Python 访问包，并记录输入、配置、工具版本和生成选项，供 RTL 构建与测试核对。
- [ ] 在项目构建脚本中接入生成任务；重新生成仅更新指定产物目录，保留用户手写代码。
- [ ] 确定生成物的提交或发布方式，检查缺失、过期及配置不一致的产物。

自动增量生成可以在上述流程稳定后加入。缓存需要覆盖被包含文件及完整配置，不仅检查入口文件。

## 运行时接入

- [ ] 为示例总线编写异步读写回调，复用 Agent 的请求提交、响应关联和错误传播。
- [ ] 明确地址单位、访问宽度、字节序、写掩码和超时规则，验证字段访问所需的总线操作。
- [ ] 由测试环境创建访问对象并绑定回调；每个 DUT 实例拥有独立的可变状态。
- [ ] 核对普通读写、只读、只写和特殊字段的生成器支持范围，明确不支持的行为如何处理。

回调应等待协议要求的完整结果。读取返回响应数据，写入按协议检查完成状态；输入接受事件不能代替最终结果。生命周期沿用现有 Execution 和 Agent，不新增仿真调度器或寄存器专用 Driver。

## 示例与验收

示例至少包含普通读写寄存器、只读状态、复位值、寄存器数组及一个写一清零字段。特殊字段同时用于检验生成器和总线适配的边界，不在验证之前承诺完整 SystemRDL 行为支持。

- [ ] 从干净产物目录生成并加载访问包，修改字段位置后重新生成，具名访问使用更新后的定义。
- [ ] 使用测试替身核对地址、宽度、数据和掩码，再通过一个寄存器 RTL 示例完成端到端读写。
- [ ] 注入总线错误、响应超时和外部取消，确认错误到达调用者，任务及 watcher 正常释放。
- [ ] 同时创建两个实例，验证绑定和状态隔离；按选定部署方式检查运行环境的依赖。
- [ ] 补充构建命令、最小使用示例、支持范围和生成物维护说明。

第一阶段的完成条件是规格生成与总线访问形成可运行流程。完整寄存器镜像、覆盖和自动行为检查按后续阶段交付。

## 后续扩展

基础接入完成后，依据实际项目需求评估以下工作：

- 独立的寄存器参考模型与预期值镜像，明确写一清零、读取副作用、复位和硬件更新规则。
- 利用总线 Monitor 更新模型，覆盖来自其他主设备的访问，并定义多接口观察顺序。
- 基于规格编写访问和复位检查场景，为可随机化字段生成约束；激励、正确性检查与覆盖分别建模。
- 开发时自动生成、元数据导出、类型提示补充，以及交互式工具的运行时加载。

运行时直接解析 RDL 和完整 UVM 风格寄存器体系均不属于第一阶段目标。只有具体用例需要时，再扩展相关接口。
