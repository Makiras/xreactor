# 零基础 Quick Start 重写与验证（2026-09-29）

## 修订原因

上一轮按功能整理了指南，但入门页直接展示 fixture、异步环境、Agent 和乱序事务，
默认读者已经知道 Python、接受时刻、响应与检查的区别。示例能运行并不意味着能教会
第一次写验证的人；导出数量、索引完整和构建通过不足以证明入门文档合格。

## 新的教学结构

入口为 [从零开始](../../docs/getting-started/index.md)。主线用同一个 8 位累加器，按
assert → 手动输入与时钟 → 边界表 → Driver → Monitor/比较 → Agent → 模型/fixture
→ 流水/多批次 → 故障定位 → 覆盖率推进。每一步说明上一种写法遇到了什么问题，
再引入一个解决该问题的概念。

Python 的 def、缩进、await、async with、列表/字典、参数化、class/self、yield 等只在
首次使用时解释。先有完整的创建和清理代码，再引入 fixture；先手写期望值，再提取模型；
先观察按序响应，再将带 tag 的乱序接口作为选读变体。

各页包含文件路径、完整代码、终端命令、预期结果、逐步解释和改错练习。说明输入接受与
响应完成的区别、send 与 submit 的不同用途，以及 finish、响应预算、观察窗口的边界。
默认路径不需要 xspcomm、RTL、asyncio TaskGroup 或锁。Agent 为注册给 Execution 的实例。

教学 DUT 的使能、位宽、初始化和响应延迟都是示例显式规则，不新增框架协议假设。
native 选读仍然是 Python DUT 替身，接入项目时分别说明应替换的端口、初始化、接受条件
和响应快照；不提供伪装成可运行代码的项目占位工厂。

## 首版材料与验证

`examples/getting_started` 默认收集 16 项正常用例，覆盖零/最大值/溢出、空闲保持、
延迟快照、自动比较、有状态模型、连续输入周期、多批次、待发取消、乱序和覆盖计数。
`failure_lab.py` 需显式选择，四种故障都真实退出为失败；`native_lab.py` 也需显式运行。

`tests/integration/test_quickstart_tutorial.py` 增加 17 项检查：

- 文档完整代码与实际示例文件一致，并且所有可运行教学用例都有完整代码块。
- 四种故障的 pytest 子进程返回码、选择结果与诊断匹配文档。
- 六种文档改错操作实际产生相应失败：错误期望、忘撤 enable、响应时刻改变、Agent 比较、
  逐笔等响应使输入不连续、覆盖目标缺失。

## 后续收拢：减少文件跳转与重复检查

按读者对文件数量和维护成本的反馈，将教程目录从 20 个 Python 文件收拢为 6 个。
主线 test_accumulator.py 按教学顺序放置各测试、Driver、Monitor、Agent、模型和 fixture；
toy_dut.py 只提供 DUT 替身。故障、乱序、native 贯通和 native 安装检查各保留一个文件。
文档仍按学习步骤分页，展示主线对应段落；命令使用 `::测试函数名`，不用每章运行全部用例。

文档示例一致性检查改为匹配主线 region，覆盖全部教学段落，不再要求为每段拆一个模块。
删除六组改写源码字符串的练习回归，以及教程层的六项双后端边界矩阵；核心事务、时序、
取消和清理测试保持原位。保留四种故障命令的失败退出检查，降低对完整错误文字的依赖。
