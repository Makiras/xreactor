# 从零开始写一个验证测试

这份教程面向还不熟悉 Python、也没有搭过验证环境的人。你会用同一个 **8 位累加器**，
从“输入 3 后结果应该是 3”，逐步写到连续输入、自动检查、漏响应定位和覆盖率报告。
先跑通小例子，再改一处看看会发生什么；不需要先读 API 手册。

前半部分只需 Python，不需要 RTL、Picker 或仿真器。我们提供一个行为确定的小 DUT 替身，
让你能在普通电脑上练习写测试。它帮助学习验证代码，**不代表已经验证了真实硬件**。

## 主线只需要看两个文件

```text
examples/getting_started/
├── test_accumulator.py   本教程逐步扩展的测试：从四行断言读起
└── toy_dut.py            已提供的累加器替身，先了解端口规则即可
```

先打开 `test_accumulator.py`。测试、Driver、Monitor、Agent 和模型按教学顺序写在同一文件里，
定义紧挨着首次使用它的例子；不用跟着每一章再创建一个 Python 模块。
`# region` / `# endregion` 只是注释，部分编辑器可用它们折叠段落，Python 会忽略它们。

每页只展示当前新增的部分。**使用仓库现成文件时，定位对应段落即可，不要再次粘贴。**
如果想从空文件跟写，则按章节顺序追加代码，保留前面学过的定义和 import。
各页命令用 `文件名::测试函数名` 选择当前步骤，暂时不需要运行整份教程。

目录里另外四个 Python 文件分别用于故障练习、乱序选读、native 选读和 native 安装检查，
到相应章节再打开。文档仍按知识点分页，源码主线集中在一个文件。

## 先认识四个词

- **DUT**（被测设计）：这里是累加器；实际项目里可能是缓存、总线接口或运算单元。
- **激励**：测试送给 DUT 的输入，例如操作数 3、5。
- **期望值 / 实际值**：规格说应当得到的值 / 从 DUT 读到的值。二者相等才通过这项检查。
- **事务**：一次有意义的操作，例如“加上 3”；一次事务可能需要多个时钟周期。

Python 语法会在首次出现时解释。本教程中的 `bash` 代码块在终端执行，`python` 代码块
对应文件中的学习段落；预期输出不用复制到任何地方。
